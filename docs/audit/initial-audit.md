## A. Architecture summary (evidence-based)

| Layer | Actual implementation |
| --- | --- |
| Monorepo | npm workspaces: `backend/`, `web/`, `mobile/`, `packages/shared` (root `package.json`). Each app also carries a byte-identical copy of the shared contracts (`backend/shared`, `web/shared`, `mobile/shared`) so apps can be split into standalone repos; build scripts rebuild every copy. |
| Backend | Node ≥22, Express 4, TypeScript (ESM), Zod validation on every route body/query (one exception: the signed WhatsApp webhook, verified by HMAC instead), Prisma 6 + PostgreSQL 16, JWT access tokens (15 min, HS256, issuer/audience pinned) + rotating refresh tokens (30 d, SHA-256 hashed, reuse detection revokes all sessions), bcrypt(12), helmet, CORS allow-list (wildcard supported for previews), `express-rate-limit` (global 300/15 min/IP; login 10/15 min; refresh 30/15 min), pino logging with credential redaction, standardized error envelope `{ error: { code, message }, requestId }`. |
| Tenancy | Membership-derived tenant context: the API never trusts a client-supplied `businessId`. Authorization = business permission grants (roles) or platform permission grants, enforced server-side by middleware on all 135 routes. The Prisma schema reinforces this with composite foreign keys `(id, businessId)` across tenant tables, so cross-business references are rejected by the database itself. |
| Business model | Configurable multi-business-type platform: `BusinessTemplate` (terminology, modules, item types, workflow stages/transitions, custom fields) with per-business overrides (`BusinessConfiguration`), revision history, platform module allow-lists, plan limits, and subscription billing with manual payment review (PENDING → UNDER_REVIEW → APPROVE/REJECT, SUPER_ADMIN-only review). |
| Modules (API) | auth, customers, measurements, catalog (generic items), orders (+ configurable workflow + legacy status), payments (+ PDF receipts, reversals, customer ledger), reports (dashboard, summary), audit, staff/roles, business configuration, inventory (items/variants/locations/movements, weighted-average costing), suppliers, purchasing (PO/partial receipt/settlements), cashbook, double-entry accounting (journals, trial balance, P&L, balance sheet), bank reconciliation, subscriptions, platform admin (businesses, owners, members, staff, templates, plans, payment review, billing settings/report CSV, branding, health), WhatsApp notifications (queued worker with claim-by-status, Meta webhook with signature verification), offline sync (push/pull). |
| Web | React 19 + Vite 8 SPA, no router (state-driven `View` union persisted in `sessionStorage`; tokens in `sessionStorage`). Business workspace (Overview, Orders, Catalog, Customers, Measurements, Payments, WhatsApp notifications, Operations & finance ERP, Subscription, Business settings, staff/roles admin, rule-based chat assistant) and Platform console (Overview, Businesses, Templates, Subscriptions, Plans, Payment review, Billing reports, Platform settings/branding, Platform staff, Audit, System health) in one 4,539-line `main.tsx` plus `ErpWorkspace.tsx`, `BusinessTeamAdmin.tsx`, `ChatAssistant.tsx`, `BusinessStructureEditors.tsx`. |
